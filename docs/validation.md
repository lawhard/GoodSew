# Validation — 0.11.0

Performed September 7, 2026.

- 42 automated Node test entries pass, including seven original geometry/pipeline suites and new project persistence, validation, machine limits, layer-order constraints, bean stitches, timing, sewing sheets, raster options, SVG import, and color-transition regressions.
- DOM control smoke checks pass: app boot and font loading, generation and spool list, PES export, undo after New, groups through undo, stitch-based hoop fitting, basting first, fabric settings, named autosave, and empty-project restoration.
- Exported PES and DST decoded with independent `pyembroidery==1.5.1`: stitch counts, color changes, dimensions, end commands, and PES needle coordinates match the expected plan within 0.1 mm. See the shipped generator/reader tests to reproduce.
- Seven additional tests cover independently generated PES v1/v6 files, custom thread names/colors, exact coordinate round trips, standalone PEC, malformed streams, thread topology, tube bounds, and overlap height. Independent fixtures are generated by `test/gen_viewer_fixtures.py` using pyembroidery 1.5.1.
- Real in-app browser checks: generated project renders in WebGL; exported PES and independent PES v6 open correctly; custom thread names/colors survive; playback, macro detail, material finish, diameter, and lighting controls work without shader errors. Closing an imported preview retains the original editable project. PNG capture was invoked without JavaScript errors; browser download persistence was not independently confirmed.
- Production build syntax-checks every application module and packages public assets only.

Not performed: native SVG CTM verification, physical transfer to an SE700, stitching fabric, touchscreen testing, or large-file GPU stress testing. Canvas drawing is stubbed in DOM tests; the separate real-browser checks above cover the 3D viewer. Machine acceptance, tension, thread compression, fabric deformation, and physical stitch quality are not certified. The renderer uses explicit material and geometric estimates, not measured fabric physics.

The request said SC700; the archive and verified documentation are SE700. That assumption is stated in the README and app profile.

Smooth satin regression checks verify two rail crossings per cycle without same-rail edge steps, plus preservation of a letter-like counter with underlay. The preset was applied to the sample lettering in the real browser and inspected in Thread Lab. This does not certify curved-letter digitization or physical coverage.


0.11.0 adds paired-rail, ring-counter, alphabet, persistence/transform, independent coordinate decoding, atomic command, revision-conflict, idempotency, undo, rejection, and isolated candidate compilation tests. The live MCP stdio adapter successfully discovered seven tools, read the paired browser project, applied satin refinements once despite a duplicate request, compiled stitches, inspected a region, verified PES positions, and returned a PNG preview. Separate integration checks cover origin/authentication, private-file exclusion, one-tab pairing, command delivery/results, and revocation. The final close-up caught and corrected a shared resampling defect: small source segments incorrectly accumulated an increasing offset, sometimes leaving only start/end points. Two additional regressions require regular samples across 100 tiny segments and short underlay moves through an S curve. The full suite passes after this shared-geometry correction.

Final saved sample: 14 editable objects, 2,168 stitches and two thread blocks. The editable .gsew reload reproduces the exported stitch count. Independent pyembroidery 1.5.1 decoding verifies the final PES has an END command and 65 × 63 mm bounds. The focused 3D image visibly confirms the G/S/e underlay chords are gone; this is still not a physical machine stitch-out.
